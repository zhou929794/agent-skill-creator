# JD Writer Skill 测试集

## 测试说明
模拟人事/用人部门的各种需求输入方式，验证Skill能否正确处理并输出结构化JD。

---

## 测试用例集

### TC-01: 口语化需求（最常见）
**输入**：
```
帮我们招一个做质量的，最好有本科学历，在厂里做过几年， 会用质量那些工具
```

**期望输出关键点**：
- 识别出"质量"→质量类岗位
- "本科学历"→学历要求
- "做过几年"→经验年限（需追问具体年数）
- "质量那些工具"→需细化为具体工具

---

### TC-02: 极简需求
**输入**：
```
招人
```

**期望输出关键点**：
- 应主动追问：招什么岗位？什么要求？
- 不应直接生成模糊JD

---

### TC-03: 完整但口语化
**输入**：
```
招个研发工程师，要本科以上机械专业，3年以上经验，熟练使用SolidWorks， 有汽车行业经验优先
```

**期望输出关键点**：
- 正确提取：本科、机械专业、3年经验、SolidWorks
- 正确识别：汽车行业经验为优先项

---

### TC-04: 纯职责描述
**输入**：
```
负责新产品设计开发，负责模具跟进，负责技术文档编写
```

**期望输出关键点**：
- 将职责转化为任职要求（需追问学历、经验等）
- 输出结构化JD

---

### TC-05: 矛盾信息
**输入**：
```
招个品质主管，要本科但其实大专也行，要5年经验但2年也考虑
```

**期望输出关键点**：
- 识别出需求中的矛盾/松动空间
- 输出时明确：本科（大专可议）、5年（可议至3年）

---

### TC-06: 大量专业术语
**输入**：
```
QE工程师，要求IATF16949体系经验，熟练运用SPC MSA FMEA， 有主机厂或者tier1经验优先
```

**期望输出关键点**：
- 正确识别专业术语：QE、SPC、MSA、FMEA、IATF16949
- 识别：主机厂/tier1经验→优先项

---

### TC-07: 仅有岗位名称
**输入**：
```
PMC
```

**期望输出关键点**：
- 识别PMC为供应链类岗位
- 主动补充该岗位的常见要求（经验、技能等）

---

### TC-08: 招聘网站原话
**输入**：
```
【岗位职责】
1.负责新产品结构设计
2.负责样机制作和测试
3.协助解决生产异常

【任职要求】
1.大专以上学历
2.机械相关专业
3.熟练使用CAD
4.有相关工作经验优先
```

**期望输出关键点**：
- 将散乱的岗位职责整合
- 将模糊要求明确化："熟练使用CAD"→具体软件

---

### TC-09: 模糊加分项

### TC-11: 涉及薪资范围
**输入**：
```

```

**期望输出关键点**：

### TC-12: 地域+通勤要求
**输入**：
```

```

**期望输出关键点**：

**期望输出关键点**：

- 仍需输出标准JD结构

---

### TC-14: 多岗位需求
**输入**：
```

```

**期望输出关键点**：
- 拆分为3个独立JD
- 每个独立完整

---

### TC-15: 转行过来的人员需求
**输入**：
```
招个做质量管理的，最好是从工程转过来的，懂工艺
```

**期望输出关键点**：
- 识别：质量岗位，有工程/工艺背景优先
- 输出包含跨职能经验要求

## 评分标准

| 维度 | 权重 | 评分标准 |
|------|------|----------|
| 信息提取完整性 | 30% | 是否提取了所有关键信息 |
| 术语识别准确性 | 20% | 专业术语是否识别正确 |
| 结构化程度 | 20% | 输出是否符合标准模板 |
| 追问合理性 | 15% | 信息不全时追问是否到位 |
| 可验证性 | 15% | 输出是否可量化、可验证 |

### 主要发现

**优点**：
1. ✅ 专业术语识别准确（制造业术语全覆盖）
2. ✅ 结构化输出规范
3. ✅ 软技能处理合理（面试验证项）
4. ✅ 矛盾信息识别到位

**待改进点**：
1. ⚠️ 极简输入时追问范围可更精准
2. ⚠️ 招聘网站原话处理时可进一步优化
3. ⚠️ PMC等缩写岗位的自动补充可更丰富

### 改进建议

1. **增加追问模板**：针对常见岗位提供预设追问项
2. **扩充缩写词典**：PMC、QE、SQE等常见缩写全覆盖
3. **增加容错处理**：对模糊输入提供多个选项让用户选择
