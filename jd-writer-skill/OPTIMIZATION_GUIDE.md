# JD Writer Skill - 优化说明

## v2.0 优化概览（HR/招聘专家视角）

---

## 一、核心优化方向

| 优化点 | v1.0 | v2.0 | 优化理由 |
|--------|-------|-------|----------|
| 任职要求分类 | 必须项+加分项 | 必须项+优先项+软技能 | 分层更符合招聘决策逻辑 |
| 岗位职责结构 | 职责简单列表 | 【动词+对象+结果 | 职责更明确，与简历匹配更精准 |
| 基础信息扩展 | 5个字段 | 8个字段（新增汇报关系、下属人数） | 更符合招聘决策逻辑 |
| 简历匹配参考 | 简单JSON | 结构化字段指引 | 便于后续AI标准化提取简历信息 |
| 制造业专项 | 简单提示 | 专项动词表+岗位优化 | 更贴合行业特性 |

---

## 二、详细优化说明

### 1. 任职要求分类优化（招聘决策逻辑）

**原结构**
```
### 必须项 [必须]
### 加分项 [加分]
```

**新结构**
```
### 必须项（不满足直接淘汰） [必须]
### 优先项（满足则优先录用） [优先]
### 软技能要求
```

**优化理由**：
- 必须项：真正的硬门槛，不满足就直接淘汰
- 优先项：不是必须，但有则优先（比加分更明确是"优先录用"）
- 软技能：虽然难量化，但在招聘中很重要，单独列出来

---

### 2. 岗位职责标准化（动词精准化）

**原格式**
```
1. 负责新产品设计开发
```

**新格式**
```
1. **主导**新产品设计开发，从概念设计到量产导入全流程跟进，确保项目按期交付并达成质量目标
```

**优化理由**：
- 动词标准化（避免用"负责"
- 明确动作对象
- 明确产生的结果/目标
- 便于后续简历匹配时，AI更容易找到对应项目经验

---

### 3. 基础信息扩展（决策辅助信息）

**新增字段**：
- **汇报关系**：向谁汇报（判断层级关系
- **下属人数**：是否带人、带多少人（判断管理属性

**优化理由**：
- 这些信息在招聘决策中非常重要
- 便于简历中也会有相关描述
- 增加匹配维度更全面

---

### 4. 简历匹配参考优化（AI友好型）

**新增结构**：
```json
{
  "resume_extraction": {
    "target_fields": ["学历", "专业", "工作年限", ...],
    "attention_points": ["重点关注XX", "重点关注YY"]
  }
}
```

**优化理由**：
- 明确告诉后续AI从简历中提取哪些字段
- 明确告诉AI要关注哪些重点
- 标准化提取方式
- 后续处理统一

---

### 5. 动词表（招聘专家推荐）

```
管理类：主导、统筹、管理、负责、规划、监督、考核
研发类：设计、开发、制定、优化、分析、测试、验证
生产类：执行、跟进、管控、提升、改善、保障
运营类：协调、对接、统计、分析、优化、执行
职能类：编写、整理、协助、沟通、处理、维护
```

**优化理由**：
- 标准化职责描述统一
- 便于后续简历匹配（动词对应
- 避免模糊词如"负责"

## 三、制造业岗位专项优化

| 岗位类别 | v1.0 | v2.0 |
|----------|------|------|
| 研发类 | 简单提示 | 强调APQP/PPAP/DOE/具体工具 |
| 生产类 | 简单提示 | 强调5S/精益/IATF/现场管理 |
| 质量类 | 简单提示 | 强调QC工具/SPC/MSA/FMEA |
| 供应链类 | 无 | 新增：成本管控/供应商/ERP/MES |

## 四、从简历匹配角度考虑的设计要点

1. **职责与要求对应**
   - 每个职责最好有对应的要求
   - 职责动词尽量具体，便于简历找到类似项目

2. **所有要求可验证**
   - 避免"优秀的沟通能力"→"具备良好的跨部门沟通协调能力"
   - 避免"懂软件"→"熟练使用SolidWorks"

3. **分层明确**
   - 必须项真淘汰型项
   - 优先项是加分不是淘汰型
   - 软技能作参考评估

4. **简历提取明确指导**
   - 明确告诉AI从简历中提取哪些
   - 明确告诉重点
